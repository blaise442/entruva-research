Week one of the experiment was data collection, and it is nearly done.

The trace index now holds 44,917 rows from five sources: tau-bench retail
and airline trajectories (1,980), SWE-bench agent runs on the lite split
(1,167), AgentDojo runs including prompt-injection attacks (36,678),
WebArena v2 execution traces (4,818), and 274 agentic incidents from the AI
Incident Database kept by a documented keyword rule. Every raw artifact has
a URL, fetch date, row count, SHA-256 checksum, and license recorded in a
manifest that the pipeline re-verifies on every run. One command rebuilds
the index and the data report from raw files.

The sixth source, ERC-8004 on-chain registry events, has a collector ready
and tested but waits on an RPC endpoint. The registries are young, so we
expect sparse rows there either way.

One honest gap: none of the published trace sets includes per-step latency,
which was one of the telemetry families named in the hypothesis. Tool-call
sequences, error signals, and task lengths are present. The latency family
will stay unavailable unless we generate traces ourselves (a spend decision)
or a dataset owner shares richer traces; we have drafted a request for one
such dataset.

Next is Gate 2: a preregistered check that the dataset is large and balanced
enough to answer the question at all, including a simulated power estimate.
If it is not, we reduce scope and say so here.
