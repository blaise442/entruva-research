## 2026-10-23: Phase 2 analysis clarifications (no threshold change)
- What changed: (1) The primary telemetry model is gradient boosting on telemetry features plus every input the naive baseline sees (model identity, task type, task length), so the paired delta measures the incremental value of telemetry as a rating factor. A telemetry-only variant (no model identity) is reported as a sensitivity. (2) Incident rows are excluded from all models: they carry no telemetry and are all failures. (3) Per-step latency cannot be built (no source publishes it); the only duration is AgentDojo's per-run total, used as a feature where present. (4) Held-out split is by whole agents per benchmark source (20 percent, ceil), frozen in research/splits/primary_split.json before any model was fit, because no benchmark row has a timestamp. (5) Clause 3's "monotone enough" is operationalised as Spearman rank correlation between decile index and decile failure rate above 0.8, fixed in src/models/run_primary.py before any result was computed; a flat decile table scores 0.
- Why: the preregistration fixes the model class, seeds and metrics but not the input set or the monotonicity rule; these choices were made before any model was fit or any test label inspected.
- Decided by: executing agent during Phase 2, for founder review at Gate 3.
- Effect on preregistered thresholds: none.

## 2026-10-25: manipulation-cost dollar floor set (clause 4)
- What changed: clause 4's floor is fixed as a ratio. The cheapest S3 intervention that lowers an agent's predicted risk by one decile while its true failure rate is unchanged must cost at least 3 times the annual premium saving that one-decile drop would produce, counting the attack as a one-time cost against one year of saving. Attack cost is measured in dollars of compute or fees; the premium saving comes from the hypothetical premium schedule used in clause 3, so no premium is quoted or invented.
- Why: deferred at Gate 1 (entry 2026-10-19); the preregistration requires it before Phase 3 begins and before any adversarial data exists. A ratio does not depend on a premium we have not priced. A factor of 1 is the weakest rational-attacker standard; 3 leaves a margin for attackers with cheaper compute or non-monetary motives without being a bar no scoring system could clear.
- Decided by: founder, 2026-10-25, on the executing agent's recommendation. Set after the Phase 2 prediction results were known and before any Phase 3 adversarial run; this ordering is stated so a reader can weigh it.
- Effect on preregistered thresholds: fills the TODO in clause 4; no other threshold changes.

## 2026-10-27: Phase 3 attack, decile and breakeven definitions (clause 4 operationalised)
- What changed: (1) Attacks are feature-level functions on held-out feature rows, each stating in words the trace change an operator would make, with the coupling rule that every feature the extractor would move for that change moves. The four attacks: error suppression (errors to zero, each swallowed error becomes a silent identical retry), retry diversification (repeat ratio to zero), call shaping (k added padding calls with distinct arguments), message shaping (message length scaled by a factor). exit_status is in scope for an attacker but none of the four changes it, because the observed values are submission statuses, not error codes. (2) An agent's decile is the decile of its mean held-out predicted probability against the Phase 2 row-level decile boundaries of the untransformed held-out predictions. Agents in decile 1 cannot move and are reported as such. An attack moves one decile when it does so for at least half of the held-out agents that can move; the any-agent reading is reported beside it. (3) The premium saving uses predicted probabilities per decile, not observed rates, because the premium is defined on predicted risk. (4) Breakeven exposure X* = (E + c R) / (3 dp), with E the one-time cost, c the per-run cost, R runs per year and dp the drop in mean predicted probability; clause 4 passes in a scenario when the cheapest priced decile-moving attack has X* above the scenario's exposure. (5) Scenario grid: runs per year in {1000, 100000}; annual exposure in USD in {1000, 10000, 100000, 1000000}; one-time cost E in USD in {0, 10000}; 16 cells, all labelled scenarios. Clause 4 passes only if it passes in every cell. (6) Per-run cost: added characters converted to tokens with tiktoken using the chars-per-token ratio measured on each source's own traces (encoding_for_model where tiktoken knows the model id, otherwise cl100k_base as a labelled fallback), charged at the vendor's public list price for input and an equal-size output. Models with no public list price are unpriced; an unpriced attack never counts as the cheapest; a model whose every decile-moving attack is unpriced gets "not evaluable" for clause 4.
- Why: the preregistration fixes the floor as a ratio but not the premium definition, the decile unit, the attack set or the cost model.
- Decided by: executing agent, on the design the founder approved 2026-10-27, before any attack was run.
- Effect on preregistered thresholds: none; this fixes how clause 4 is computed.

## 2026-10-27: S4 flywheel constants
- What changed: the simulation has 500 agents whose true failure rates are resampled from the Phase 2 held-out agents' observed rates, 50 resampled held-out rows per agent per round, 12 rounds with a burn-in of 4, attacker fraction f from 0 to 1 in steps of 0.05, seed 20261017, one run per scenario cell of the grid above. Each round the insurer refits the Phase 2 model class on the previous round's observed telemetry (attacked rows included) and true outcomes; a round whose outcomes are all one class keeps the previous scorer and is flagged. A round is one year of runs. Attackers are rational: they apply the cheapest priced attack only when the breakeven under the current scorer says it pays, paying E once. Converged: AUC against true failure within the Phase 2 held-out GBM AUC CI over the rounds after burn-in. Collapsed: AUC below the Phase 2 naive baseline AUC in every round after burn-in. The boundary is the smallest f at which collapse holds. All outputs carry "synthetic" in the filename and feed no headline result.
- Why: the preregistration names the simulation and its two outcomes but fixes no constants.
- Decided by: founder (the scorer-refit feedback loop) and executing agent (constants), 2026-10-27, before the simulation was written.
- Effect on preregistered thresholds: none.

## 2026-10-28: Phase 3 corrections from the whole-branch review (before the rerun)
- What changed: (1) Call shaping gains the direction the design named and the first run omitted: k < 0 drops up to |k| redundant calls, bounded by the row's repeated-call count, with every coupled feature moved and no per-run cost; strengths are now -32 to 32. (2) mean_text_len is coupled over n_tool_calls, as the extractor computes it, not over task_length_steps; this changes call shaping's mean_text_len shift and message shaping's per-run characters on sources where steps exceed tool calls. (3) dp in the breakeven is the difference of the decile mean predicted probabilities before and after the attack, as the design's Part B states; the first run used the agent's own mean-probability drop, which understates the saving for an agent that crosses a boundary by a small margin. The decile means are now in the S3 result. (4) An attack with no movable held-out agent reports "not evaluable", never a pass. (5) The S4 attacker attacks when its annual saving exceeds its cost (dp x X > E + c R); the first run used the insurer's 3x floor as the attacker's rule, which overstates attackers. (6) S4 round 0 uses the Phase 2 scorer (the refit on the train agents), as the design states; the first run fit round 0 on the held-out rows. (7) In S4 the attacker's dp is its own mean predicted-probability drop under the current scorer, because S4 premiums are charged per agent on that mean, so what an attacker saves is what it is charged; this is a simplification of the Part B decile definition and is stated here.
- Why: a fresh reviewer read the branch after the first run and found these against the design and the extractor. The first run's result files (2026-10-27 S3 and S4) are superseded and remain in git history at commit 1488a19; the corrected runs are dated 2026-10-28.
- Decided by: executing agent, 2026-10-28, after the first run's numbers were known and before the rerun; this ordering is stated so a reader can weigh it. The scenario grid, E values, floor and every S4 constant are unchanged.
- Effect on preregistered thresholds: none.

## 2026-10-28: Phase 4 cross-check rules (before the run)
- What changed: the reduced Phase 4 (entry above) is pinned to these rules before any run. Ethereum cross-check against Harvard Dataverse doi:10.7910/DVN/HJZW8Q (CC0 1.0, released 2026-07-01, agents 0 to 9999), four checks with no tolerance: (1) agents_core: for every agent, mint_block equals the block of our Registered event, mint_tx_hash equals our transaction hash (lower-case hex, no prefix), owner_wallet equals the owner our Transfer events give at the observation block; the observation block is inferred as the smallest block at which every agent's owner agrees, None if no block in our range does, and it is reported as inferred because the data dictionary states none. (2) transfer_history: every row (agent_id, tx_hash, log_index) exists among our Transfer events, and our count of non-mint transfers for those agents up to their maximum block equals their row count. (3) agent_feedback_records: every row (agent_id, client_address, feedback_index) exists among our NewFeedback events. (4) agent_reputation_summary: feedback_count_total is at most our NewFeedback count per agent (our fetch of 2026-10-25 is later than their snapshot), with the number of equal agents reported. Verdict "matches row for row" only if all four hold for every row; otherwise the failing checks are named and the disagreeing rows published. Base mainnet and BNB Smart Chain mainnet are fetched with the existing collector through the keyless endpoints https://base-rpc.publicnode.com and https://bsc-rpc.publicnode.com (addresses from the curated README at commit b9e466c250744a7e06b13dff9d3c2844ed64f825). Count check per chain: our Registered count equals our maximum agent id plus one, and that maximum is at most the newest token_id the 8004scan public API returns on the request date (one anonymous request per chain); the API's own total field is recorded, not used, because it counts agents with a registration file.
- Why: the data dictionary states no observation block; our fetch is later than the Dataverse snapshot; the anonymous API tier cannot page a million Base agents and a key means a sign-up; metadata tables are not compared because the collection never fetched off-chain metadata.
- Decided by: executing agent under the founder's instruction to proceed, 2026-10-28, before any Phase 4 run.
- Effect on preregistered thresholds: none. Phase 4 produces no verdict on H1.

## 2026-10-29: Base and BNB reduced to a two-day window (before the run)
- What changed: the keyless endpoints named in the entry above serve anonymous clients only a recent slice of history (measured 2026-10-29: eth_getLogs answers 403 Forbidden beyond about 3 days on BNB Smart Chain and about 46 days on Base; the official Base and BNB Chain endpoints reject eth_getLogs outright, and the founder's Alchemy app has neither network enabled). A full-history fetch of either chain is therefore not possible at zero spend tonight. Base and BNB are fetched over the two days before each chain's head (WINDOW_BLOCKS 86,000 on Base and 380,000 on BNB, chosen from measured block ages; the exact span is taken from the first and last block timestamps and recorded with the fetch), and the same two-day window is cut from the end of the full Ethereum file using the 12-second slot time (14,400 blocks). The statistics compared across the three chains are window statistics: registrations and registrations per day, feedback events and feedback per day, agents receiving feedback, the share of those agents with a single feedback giver, and distinct givers. The 8004scan count check is reported as not applicable for a windowed fetch (the newest token id is still recorded); it runs as planned on the full Ethereum file. The full-history Base and BNB descriptives stay open until a full-history source is available.
- Why: the alternative was no Base or BNB data at all; a windowed comparison is weaker than the full-history one the Gate 4 decision asked for, and it is labelled as such everywhere it appears.
- Decided by: executing agent under the founder's instruction to proceed and approve, 2026-10-29, before the run.
- Effect on preregistered thresholds: none.
